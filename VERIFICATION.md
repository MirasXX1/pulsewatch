# PulseWatch: результаты проверки 24 октября 2026

## Исправления

1. **Подтверждённая ошибка:** успешный фоновый refresh стирал сообщение о неудачном добавлении сайта. Воспроизведено падающим DOM-тестом, затем исправлено: ошибки действий отделены от ошибок загрузки.
2. **Подтверждённая ошибка:** более старый ответ списка мог прийти после добавления и скрыть новый сайт. Воспроизведено тестом с задержанным первым HTTP-ответом, затем исправлено: применяется только последний запрос; ответы после unmount/навигации игнорируются.
3. **Устранён риск запуска:** `next dev` и `next build` использовали один `.next`. Теперь dev использует `.next`, а build/start — `.next-build`. Это предотвращает перезапись ресурсов открытого dev-сервера во время проверки сборки. Не доказано, что это была единственная причина сообщения пользователя «сайт не работает».
4. Добавлен `frontend/app/icon.svg`: зелёная линия пульса на тёмном фоне. Иконка подключается файловой конвенцией App Router, без ручного `metadata.icons`.

Backend, правила HTTP-проверок и данные пользователя при этих исправлениях не менялись.

## Что не удалось подтвердить

На Mac обнаружены работающие процессы: frontend `127.0.0.1:3000`, backend `127.0.0.1:8080`, PostgreSQL `127.0.0.1:5433`. После изменения Next config PID frontend изменился — dev-сервер перезапустился и снова слушает порт.

Но HTTP-запрос из агентской сессии к `127.0.0.1:3000` завершился **`[Errno 1] Operation not permitted`**. Docker socket также недоступен с `permission denied`. Это ограничения sandbox: они не доказывают, что сервер отвечает ошибкой в обычном браузере, и не позволяют объявить живой сайт полностью проверенным.

- Live smoke был **запущен и завершился неуспешно на первом соединении**. Его отчёт: `.local/verification/smoke.json`. Создания/удаления реальных сайтов во время этой попытки не было.
- Сетевой класс `ProbeTest` пропущен из-за запрета bind loopback-сокетов. PostgreSQL integration tests не выполнены из этой сессии.
- Maven offline test остановился из-за отсутствующего Surefire JUnit provider. Java-тесты запускались непосредственно через доступный Jupiter engine; успешный `mvn verify` не заявляется.
- jsdom не является настоящим браузером. Визуальная адаптивность и реальное HTTP-взаимодействие браузера с сервером не объявляются проверенными.

## Полная проверка вне sandbox

Из корня проекта, с готовым Docker Engine:

```bash
bash scripts/run-local.sh verify
```

Эта команда выполняет PostgreSQL integration tests, Maven build, frontend-тесты, TypeScript, production build и проверку артефактов. Для живого сценария при запущенных backend/frontend:

```bash
bash scripts/run-local.sh smoke
```

Smoke проверяет HTML, единственный favicon, загрузку JS/CSS, прямой backend, frontend API proxy, блокировку небезопасных URL, создание временного сайта, первую автоматическую проверку, ручную проверку, следующий 60-секундный цикл, историю/процент и удаление временного сайта. Ожидание планировщика — до 90 секунд. Оригинальные мониторы пользователя не удаляются. Результат записывается в `.local/verification/smoke.json`; успешный результат имеет `status: "passed"`.
